## LostFrameWork

#### 1.说明
很多开发过程中存在大量重复轮子，因此该架构作为个人整合框架进行开发。  
后面会加入编辑器功能，对这些模块进行一个开关设置，项目结束后再进行整理，框架优先度降低。  
对于开发而言，并不是功能越多越好，根据需求逐渐扩展。最小开发规模，因此对一些可视化工具暂时不做支持。  
可视化工具会增加项目开发和维护难度，不建议程序员使用可视化进行开发游戏，这个部分应当由策划和美术进行负重非代码部分的配置。
#### 2.核心理念
大道至简，由简化繁，由繁化简。  
道理往往朴实无华  
尽量不适用其他第三方库，以及严格的隔离控制代码的复杂度  
低侵入度（框架尽可能不影响已有功能的正常使用）  
高可读性（面向接口，降低信息密度）  
严格隔离（使用程序集进行隔离代码）

#### 3.特点
-  异步:仅使用一种异步方案，即asyn，在Unity中可以使用协程、回调、asyn等异步方案，为了避免混淆，仅使用asyn的异步方案，所有异步都支持async的同步操作。当然你可以使用uniTask进行替换。
-  事件：使用接口来控制事件的使用范围，不允许直接使用EventManager进行订阅和推广,同时基于结构体进行订阅和推广，并对事件推广进行封装
-  访问性限制：程序集和接口两个地方对访问性进行限制，所有的实现类都进行私有处理。使用程序集对代码的依赖进行控制，减少依赖

#### 4.补充功能
- [x] I10nKit:本地化工具，使用I2作为现有功能进行封装。后面也会对I2进行剥离，通过单独的表格进行控制。
- [ ] 网络模块：提供基本的模块和接口，便于自定义协议。当前默认接入的为GeekServer。GeekServer在后面也会进行替换成更适合开发的框架（而非是ECS框架，ECS框架执行效率虽然很高，但工具应当去适应人，而非人去适应工具）
- [ ] 库存系统：简易的库存系统，以便于快速实现背包和仓库等功能。
- [ ] 动效系统：将复杂的效果限制在编辑器内进行配置，减少代码的复杂度和职责（参考Feel）
- [ ] 技能动作系统：RPG是一个经常遇到的类型，因此角色技能和对应的动作序列是一个必要的功能。
- [ ] 调度器：对于大量的、复杂的任务，不可能当场计算完成，因此需要通过调度器进行控制，同时所有调度器都会受到总控的控制，根据设置的权重进行自动管理每帧的运行时间，以确保游戏的正常运行。
- [ ] 日志和控制台：在游戏中参看日志，同时输入命令进行监控游戏的状态是一个常见的功能，因此游戏会进行内置一个这样的系统
- [ ] CSV管理工具：提供CSV文件的读写功能，方便策划和美术进行数据交换。不使用Excel，因为Excel不便于git的版本控制。表格数据直接以csv格式进行读取。支持检查数据的有效性。
